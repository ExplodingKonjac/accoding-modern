# OJ Modern 与 OJPeeker 整合方案

日期：2026-10-20  
状态：用户已于 2026-10-20 验收通过；正式部署与发布

本次以本机现有“代码采集”后端作为唯一 OJ 数据采集入口。同一轮采集取得源码、成绩、题目和评测明细，同时驱动现有代码核查与 Peeker 教学统计，再将核查结果和教学数据同步到 server3。server3 保存数据并提供教学查询及管理后台，不再运行独立 Peeker watch 或另一套 OJ 采集进程。OJ Modern 按现有设计规范重写教学界面。班级和名册统一在后台管理，OJ Modern 只选择已有班级，提供成绩分析、补题、代码核查与导出。

工作台从当前 OJ 登录页面读取可管理的小组，用小组 ID 对应课程。比赛、成员和教学分析直接读取云端已经同步的数据，不再要求连接教学账号。

## 1. 权限与使用方式

### 1.1 查看数据

浏览器沿用原班级管理读取比赛列表的方式，通过同源请求读取 `/group/index` 的“可管理的所有小组”表格。请求自动携带当前 OJ 登录态，不读取 Cookie，不提交账号密码，也不新增脚本管理器权限。小组按 ID 对应后台课程；尚未采集的组显示“暂无同步数据”。直连和 VPN 页面均使用现有 URL 适配。

教学服务的比赛、名册、成绩、提交统计、学生和学期分析及导出接口公开只读。前端课程选择对应当前 OJ 账号的小组，这一筛选用于页面展示，不作为云端访问控制。

### 1.2 后台管理

创建、修改、归档班级，导入名册和查看名册修改历史仍需后台登录，服务端根据该账号的 OJ 管理小组限制修改范围。后台使用独立的 `/admin/bootstrap` 读取管理范围。已有核查写入凭证继续服务于核查保存。

工作台的服务设置仅保存地址。浏览器缓存小组和教学查询结果 5 分钟，查询按服务地址、课程、班级、比赛和筛选条件区分；OJ 小组缓存按当前页面的账号 ID 区分。关闭重开工作台或页面跳转可复用缓存；“刷新数据”清除缓存后重读，投屏定时刷新及文件导出绕过缓存。

### 1.3 前后台操作边界

| 操作 | 管理后台 | OJ Modern |
|---|---|---|
| 选择课程、班级 | 管理范围内 | 当前 OJ 账号的小组 |
| 创建、重命名、归档班级 | 支持 | 不提供 |
| 导入、修改名册及班级归属 | 支持 | 不提供 |
| 设置重修标记、修正学生身份关联 | 支持 | 不提供 |
| 查看成员、成绩、提交和分析 | 支持必要查询 | 支持 |
| 导出成绩、学期分析和核查结果 | 按页面需要提供 | 支持 |
| 修改采集连接和服务配置 | 平台运维操作 | 不提供 |

后台管理同样受 OJ 管理小组范围约束。普通课程管理员可以管理自己范围内的全部班级，不需要平台运维逐班授权。

## 2. 代码与服务组织

| 部分 | 实施方式 |
|---|---|
| 本机代码采集后端 | 唯一采集入口，复用现有 OJ 会话、分页、源码缓存、规则核查与签名同步，接入 Peeker 数据适配和统计服务层 |
| Peeker 教学服务 | 保留 Python、FastAPI、SQLAlchemy、SQLite；本机作为采集后端内的模块运行，云端只接收教学快照、管理名册并提供查询 |
| OJ Modern | 保留原生 JavaScript 用户脚本，重写班级工作区及相关页面的数据接入 |
| 管理后台 | 沿用 Peeker 现有 React、Ant Design 工程，改成课程、班级、名册和同步管理页面 |
| 现有核查服务 | 保留 AI 核查、码风分析、查重、人工反馈及历史记录 |

Peeker 原有比赛、班级、学生分析前端由 Modern 中的统一界面承接；正式导航不再提供另一套同用途的教学看板。统计计算继续留在后端，Modern 负责展示和交互。

教学数据库与核查数据库分别保存，通过比赛 ID、题目 ID、OJ 用户 ID 和提交 ID 关联。此次不合并数据库，也不迁移核查规则引擎。

上游 Peeker 保留为 Git remote，本项目的必要改动在独立分支维护，便于以后合并统计修复。代码位于 `../ojpeeker-modern`，分支为 `modern-integration`；原研究副本保持不变。

本机只启动现有 `ojreview.agent` 一个后端。Peeker 作为 Python 模块和子路由挂载，不单独启动 uvicorn、watch、timer 或第二份源码缓存。两份数据库保留各自职责，采集批次以比赛 ID、截止时间和提交 ID 关联。

## 3. 后台统一管理班级和名册

### 3.1 数据关系

- OJ 小组关联服务内的课程，保存上游小组标识；小组名称用于显示。
- 班级使用现有稳定班级 ID，名称修改不改变关联。
- 教师班和行政班分别保存，二者并非上下级关系。
- 学生以学号识别，以 OJ 用户 ID 关联提交，后台名单姓名用于教学展示。
- 重修属性属于学生在课程内的归属信息。

Peeker 当前课程标识使用小组名称，接口改造时补齐上游小组关联，避免以显示名称判断管理权限。

### 3.2 后台页面

| 页面 | 功能 |
|---|---|
| 课程 | 列出可管理小组下的全部课程，维护课程展示信息、当前学期及归档状态 |
| 班级 | 创建教师班、行政班，修改名称，查看成员，归档班级 |
| 名册 | 导入 XLS/XLSX/CSV，调整归属和重修标记，处理未匹配的 OJ 账号 |
| 比赛与同步 | 查看比赛、所属课程、同步时间和失败原因，按需补采或重新同步 |

后台可列出尚无成绩的课程和空班级，不沿用“有成绩才可选”的分析页列表规则。

### 3.3 名册导入

流程为“选择课程和目标班级 → 上传文件 → 预览字段及人员变化 → 应用”。

复用已有表格解析能力，补齐后台写入。预览显示新增、修改、移出人员及学号冲突；管理员在应用前处理冲突。学号保持文本格式，姓名不作为账号匹配依据。

一次导入只修改选定课程、班级的归属。移出班级不删除学生的历史提交和成绩。班级日常下线采用归档，历史课程仍可查询。班级名称保存为“教师名班”，界面统一显示“教师名班-人数人”，人数从名册实时计算，不写入班级名称。

名单变更保留时间、操作者和版本号。分析按当前课程名册计算，名册变化后相关统计更新；导出注明名册版本。首版不建设按任意日期还原学生归属的历史系统。

## 4. 功能去重清单

| 功能 | 当前情况 | 整合安排 |
|---|---|---|
| 班级创建、改名、删除 | Modern 本地管理，Peeker 有后台模型 | 全部迁入管理后台，插件移除相关操作 |
| 名册导入和保存 | Modern 保存在 localStorage/GM | 后台统一导入保存，停止插件名册读写与跨域名册同步 |
| 当前班级选择 | Modern 使用本地列表 | 改为服务器返回的已有班级 |
| 单场通过、尝试统计 | 两边均有 | 合为一套比赛总览，使用后台数据 |
| 逐题结果 | Modern 为 AC/WA/未尝试；Peeker 有实际分值 | 合并成分值与状态表，增加满分、部分得分、零分、未提交名单 |
| 成绩导出 | 两边均有 | Modern 保留一个入口，后台生成与页面同口径的数据 |
| 学生提交列表 | 两边均有 | 合并至学生详情，保留筛选及进入代码检查的入口 |
| 按题通过提交 | Modern 已有 | 合入逐题分析，保留每人最新 AC、全部 AC 筛选 |
| 测试点明细、错误统计 | Peeker 已有 | 接入学生详情和逐题分析 |
| 学期趋势、百分位、班级横向对比 | Peeker 已有主要计算能力 | 重写为 Modern 的学期分析与比赛对比视图 |
| 补题排行榜 | Modern 已有 | 保留算法和交互，成员统一来自后台 |
| AI 核查、码风、查重、人工反馈 | Modern 与现有核查服务已实现 | 保留，改用后台班级成员筛选 |
| 投屏看板 | Modern 已有 | 保留全屏和动画，接入统一比赛统计 |
| 题面编辑、公式修复、测试点上传、开启补题 | Modern 已有 | 保留现有实现和 OJ 操作权限 |

服务端教学数据不可用时，插件显示连接或同步状态；不重新启用本地班级作为替代来源。原站题目编辑等独立工具继续按原来的方式工作。

## 5. OJ Modern UI 重写

### 5.1 统一布局

沿用现有 Modern 设计：浅灰背景、白色内容、蓝色操作色、左侧导航、系统中文字体。后台沿用 React/Ant Design，但使用相同颜色和排版，不增加新的前端框架。

```text
顶部：小组/课程 · 班级类型 · 班级选择 · 数据状态 · 账号/设置

左侧                     内容区
班级概览                 当前页面标题与筛选
比赛分析                 指标、图表和表格
学期分析
补题排行榜
代码复核
────────────────
管理后台 ↗
```

顶部课程列表覆盖当前账号可管理小组内的全部课程。班级选择只列后台已有班级；“全部班级”仅代表当前选定课程，不扩大到其他小组。

原“班级管理”入口改为“教学工作台”。名册管理、导入、创建、重命名、删除按钮从插件中移除，“管理后台”链接承担管理入口。

切换课程后更新班级和比赛选项；返回列表保留当前筛选。无班级时显示“暂无班级”，并提供管理后台入口。

### 5.2 班级概览

展示班级成员数、最近比赛、最近成绩与同步状态，提供进入比赛分析、学生详情和学期分析的入口。成员表只读。

### 5.3 比赛分析

统一为四个页签：

| 页签 | 内容 |
|---|---|
| 总览 | 应到、参与、未提交、均分，逐题通过与尝试概况 |
| 成绩表 | 学号、姓名、总分、通过题数、逐题分值与状态，进入学生详情 |
| 逐题分析 | 四类答题名单、错误分布、通过提交及提交历史 |
| 过程与对比 | 班级平均分曲线、比赛内进展、当前课程各班比较 |

比赛、班级和统计筛选放在统一工具栏，导出使用当前页面范围。

- 成绩表默认按总分降序、同分并列，可切换 OJ 原始名次（含罚时）；未参赛者列在末尾，搜索和分页不改变名次。成绩导出同样按总分降序，自适应列宽与行高，分数最多两位小数，冻结学号、姓名列和表头。
- 未提交名单默认折叠，没有异常时不展示空名单。
- 过程图仿照 Peeker：左侧各班平均分曲线，右侧按终点均分排列的最新班级排名；整块绘图区按横坐标定位，显示共同竖线、比赛时刻和按分数降序的各班数值。取消展开整段采样数值表。纵轴上限按实际曲线最高分取整，不再固定为比赛满分；图高 400px，可切换“放大末段”。
- 过程对比始终覆盖当前课程、当前班级类型的全部已建档班级；选择一个班只突出该班，不收窄对比范围。行政班不再隐去小班，图线开关用于主动选择显示内容。
- 逐题分析沿用原 Peeker 的汇总表：题号、标题、满分、提交人数、通过人数、通过率和平均分。选中班级后，每题可展开满分、部分得分、提交但未得分、未提交四列姓名标签；标签附判定、部分分及额外提交次数。取消“解题诊断”和错误条形图，提交记录按需展开。

### 5.4 学期分析

展示学生及班级历次得分率、名次、百分位和班级对比。不同满分的比赛用得分率比较，OJ 原始名次与本系统统计范围内的指标分别标注。

单场得分率为“本场参赛均分 ÷ 本场满分”。学期对比展示每班有效场次、平均班级位次、最好及最差位次：只统计当前课程已核实且该班有成绩的比赛，逐场按班级均分排名，再等权平均位次，同分并列。界面只保留简短字段说明，统计定义留在本方案。

原 Peeker 的 `average_score_ratio` 实际是“本场班均分 ÷ 本场最高班均分”的跨场平均，不能命名为“平均得分率”；新版页面和导出移除此误导列，不额外定义加权总评或预警评分。

### 5.5 学生详情

上方展示学期表现，整块图表支持悬停、点击及方向键逐场查看，浮层显示完整比赛名、得分/满分、得分率、课程名册内按分数并列位次和 OJ 原始名次。未参赛场次不画成零分。历次明细默认折叠；下方选择比赛查看逐题结果和提交历史。提交记录展示时间、判定、分数、语言、耗时、内存，测试点明细按需展开。

“查看代码”进入现有 Modern 提交检查页，继续使用源码、diff、AI 核查和人工反馈。Peeker 页面不重复制作源码编辑器和核查面板。

### 5.6 补题与代码复核

补题保留截止时间、按赛后补过或累计通过排序、学生和题目筛选，统一读取后台名册。首版复用现有补题查询，不为此额外建设另一套补题采集服务。

代码复核保留当前功能和导出，班级筛选及成员身份改为后台数据。现有人工结论、历史对照和核查权限流程继续使用。

### 5.7 投屏与通用交互

投屏入口统一位于教学工作台的比赛分析页，保留大字号、全屏和动画，使用后台的同一统计结果；旧的直读 OJ 统计看板不再另行挂载。投屏每 30 秒读取一次已同步快照，并显示实际采集时间。数据更新时间由本机采集任务决定，首版不另起常驻 watch；再次采集复用源码缓存。

窄屏将筛选分行、宽表局部滚动；图表可查看具体数值。加载失败保留筛选，切换班级后丢弃旧请求的结果。页面只显示必要的操作、状态和错误原因。

## 6. 采集与统计安排

### 6.1 采什么

采集比赛信息、题目映射与满分、成绩榜单、原始名次、逐题结果，以及每次提交的作者、题目、时间、得分率、判定和评测明细。

这些数据足以支持成绩、错误分布、过程曲线和学期趋势。源码正文由现有代码采集器统一获取和缓存。Peeker 只读取同一轮已采集的比赛元数据、题目满分、成绩榜单和提交评测信息，禁用其独立源码采集，云端不运行 watch。代码核查继续使用同一份源码缓存。

因此，本次不需要围绕 Peeker 的源码 64/100 并发进行优化。统一使用现有代码采集器的比赛与提交分页流程，补采 Peeker 必要的榜单和题目字段，出现实际瓶颈后再调整。

### 6.2 一轮采集如何运行

```text
本机代码采集（一个后端、一份 OJ 会话及源码缓存）
  ├─ 比赛、题目、榜单、提交流水与评测明细
  ├─ 现有代码核查、码风及查重
  └─ Peeker 数据适配、成绩统计和学期分析
       ↓ 既有签名同步通道，分别记录处理状态
server3：核查库 + 教学库 → 统一查询 API → OJ Modern
                         └─ 管理后台维护课程、班级、名册
```

采集完成后复用该快照计算，不为重试统计或同步再次下载源码。本机任务分别记录采集、核查、教学统计及两类云端同步结果；同步失败保留可重试材料。尚未通过用户验收的新插件和新服务不自动发布。

### 6.3 怎么统计

- 后台完成统计，Modern 展示结果；页面和导出共用统计实现。
- 通过题数依据 AC；实际分值沿用 Peeker 的得分率乘题目满分规则。
- 均分展示参与范围和分母，保留 Peeker 已有口径。
- 重修、特殊比赛筛选在图表、成绩表和导出中一致生效。
- 进行中比赛展示快照与同步时间，学期汇总使用已核实比赛。
- 赛后补题与比赛内成绩分开，保留现有时间范围规则。

本机采集使用现有代码采集应用中保存的 OJ 连接，采集范围按已接入小组配置。工作台按当前 OJ 页面的可管理小组列出课程；教学查询公开只读，后台修改仍按登录账号的管理范围校验。

## 7. 接口和现有代码改动

| 模块 | 主要改动 |
|---|---|
| Peeker 身份与课程接口 | 新增 OJ 用户会话、可管理小组读取及课程关联 |
| Peeker 班级与名册接口 | 使用班级 ID 查询，增加后台增改、导入和归档 |
| Peeker 统计接口 | 返回 Modern 所需字段、统计范围和同步时间，复用原服务层 |
| 代码采集 Collector / Orchestrator | 一次采集产出核查和教学数据，调用 Peeker 统计；分别显示核查、教学统计与云端同步状态，采集完成后自动同步，失败可重试已有快照 |
| Peeker watch | 不部署、不启动；源码只由统一采集器获取 |
| 代码采集前端 | 按 Modern 设计重写导航、任务列表、进度和连接设置，保留现有复核功能，增加教学统计与同步状态 |
| Modern class-manager / workspace | 重写班级选择和工作区，移除本地名册操作 |
| Modern class-storage / class-xlsx 等 | 退出插件名册流程；后台导入按需要复用解析能力 |
| Modern review / upsolve | 统一接入后台班级成员，保留现有业务逻辑 |
| Modern 请求层 | 增加教学 API 请求与会话处理，覆盖直连和 VPN |

Modern 浏览器保存当前选择、筛选、显示偏好及服务地址。查询结果在 Cache Storage 中缓存 5 分钟；名册仍以后端为准，不通过 GM 或 localStorage 维护可编辑副本。

## 8. 历史数据迁移
