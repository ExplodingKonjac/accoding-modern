# 独立补题排行榜 · 1.7.0

1.7.0 正式版，支持通过 GitHub 更新源自动更新。班级名册继续使用已有本地存储。

## 使用

1. 班级 → 选择比赛 → 读取比赛。
2. 比赛结束后，打开独立的“补题排行榜”页，点击“更新排行榜”；截止时间留空表示查询至当前服务器时间，也可指定北京时间。
3. “比赛统计”保持赛时通过数排序。“补题排行榜”独立排名，默认按赛后新增补过数降序，也可切换累计通过数；同题数并列，按学号排列，未匹配者不排名并置后。
4. 排行榜逐题显示“赛内 AC / 补过 / —”；点击“补过”直接打开首次补过代码，点击“查看补题”展示各题状态、首次赛后通过时间和对应代码；可筛选赛内 / 赛后 / 全部、题目与评测结果。
5. 可取消查询。查询失败或取消时保留上次完整结果及截止时间，不把不完整数据当作零补题。

## 口径与读取方式

- 赛内通过以原站比赛榜单为准；没有赛内 AC 且在比赛结束后至截止时间内出现 AC 才算“赛后补过”。同一学生、同一题只计一次；赛内已通过后的重复 AC 仍可查看，但不计新增补过。
- 时间区间是 `[比赛结束时间, 截止时间]`。仍未通过只针对已经确认账号的同学，未匹配保持待核对。
- 普通提交页 `/submission/index?offset=N` 使用原站筛选表单 POST（仅查询）：`problem_id`、`nickname`、`result`、`language`。按比赛题目读取全部可见赛后页，不只读取比赛内提交接口。最多两个并发请求，到达赛前记录或末页停止。
- 赛后出现的榜单未匹配账号，可先用姓名寻找候选，再读取原站个人资料的学号核验；不会仅凭同名绑定。没有可核验账号的学生仍标为待核对。
- 读取中验证题目过滤、分页推进和时间顺序；重复页面、格式异常、HTTP 错误均明确失败。整次查询上限五分钟，每题最多 1000 页，超过则提示未完成。
- 当前页只保留班级账号的结果；不保存学生代码，不上传名册，不修改 OJ 提交。
