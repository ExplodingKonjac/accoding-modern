没有服务器错误日志，不能断言具体异常栈是 ENOENT 或某一行代码。重复删除同一路径、缺失文件处理、保留记录共享文件引用均是维护者应检查的环节。

## 浏览器补丁

- 所有手动选文件和批量选文件均参与保存前检查。
- 阻止输入／答案同名、本次上传重名、覆盖已有文件，以及新增测试点缺少文件。
- 即使旧测试点标记删除，也阻止同一次保存上传同名文件，避免覆盖后又删除。
- 发现既有共享文件引用时允许编辑其他字段；若尝试删除相关记录则阻止发送并显示明确原因。
- 覆盖原站保存入口、jQuery 提交、原生表单提交。未修改后台接口，未伪造保存成功。
- 此检查基于文件名，不能自动恢复被覆盖的数据，也不能检测所有服务端缺失文件。

## 服务端参考补丁

`patches/backend-test-file-deletion.mjs` 不打包进用户脚本。维护者需按实际模型把测试点转换为 `{input, output}`，并将删除标记转换为下标集合：

```js
const plan = deletionPlan(currentCases, deletedIndices);
await removeFilesOnce(dataDirectory, plan.filenames);
// 在既有事务／并发控制下，将 plan.retained 写回题目设置。
```

要求：同一个文件只删除一次；仍被保留测试点引用的文件不删除；ENOENT 视作已删除；其他 I/O 错误仍报告；文件路径先统一验证；完整表单校验应先于文件操作。数据库更新与文件操作之间的失败须可重试，并使用题目级并发控制避免使用旧快照覆盖他人修改。

参考函数已用单元测试验证去重、共享引用保留、ENOENT 幂等、其他错误传播与路径检查。尚未接入或部署到真实后端。
