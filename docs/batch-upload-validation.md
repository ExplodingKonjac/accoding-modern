# 批量测试点上传验证

版本：1.3.0。使用用户授权的题目 10272，在 ego lite 登录环境中测试。

## 实际保存与恢复

1. 从原站下载全部原始测试数据，并保存题面与表单设置的本地快照。原有 5 组，共 10 个数据文件。
2. 复制其中两组为临时测试文件，使用新的文件名，避免覆盖既有测试点。
3. 乱序选择 4 个文件，脚本按文件名配对为 2 组，追加到原站表单。验证 `total_files=7`、4 个新增 File 对象、7 个权重和删除标记均正确。题面及原有字段未改变。
4. 经原站保存流程实际提交。重新读取编辑页确认共 7 组，并下载服务端数据核验：新增文件逐字节等于本地文件，原有 10 个文件逐字节未变。
5. 仅删除两组临时测试点，再次保存。重新下载确认文件名与文件字节集合完全等于备份，题面、权重、标签及其他设置恢复／保持原样。

测试没有提交选手代码，也没有主动发起历史提交重评。原站保存会触发其测试文件同步流程。

测试数据与备份不纳入公开仓库。真实判题机消费同步文件的全过程未单独测试。

## 本地功能检查

- 缺失答案时禁止填入，不改动现有行。
- `.in` 与 `.ans` / `.out` 自动配对，自然排序；原始文件字节不经解析或改写。
- 阻止同名文件覆盖、跨文件夹重名、同一输入同时对应 `.ans` 和 `.out`。
- 忽略隐藏文件与说明文档；ZIP 需先解压。
- 填入失败撤销本次新增行，恢复原站计数。

## 使用入口

题目编辑 → **基本设置** → **批量添加测试点** → 选择多个文件或文件夹 → 检查配对 → **填入 N 组测试点** → 检查权重 → 关闭设置窗口 → 原站 **保存**。

“填入”只修改本页表单，不会立即上传。当前采用追加模式，已有同名文件会报错；要替换已有点，先按原站方式处理旧数据。
