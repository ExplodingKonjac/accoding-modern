## 1.3.2：文件夹上传 Unknown Error 修复

用户报告失败方式为“选择文件夹”。本次开始时只有 `01.in / 01.ans` 一组，先下载备份并记录题面和设置。

旧脚本将目录选择器的 File 原样转移到普通 input，仍保留 `webkitRelativePath`。Chromium 的 [multipart 编码源码](https://github.com/chromium/chromium/blob/main/third_party/blink/renderer/core/html/forms/form_data.cc) 优先以相对路径作为 filename，普通 input 并不会自动去除目录。

- 用原有数据的临时副本构造目录上传等价的 multipart 文件名 `folder-probe/am-folder-probe.in` / `.ans`，原站返回 HTTP 200、跳转首页，正文包含 `Unknown Error`。无缓存回读确认未新增记录。
- 同一文件改为纯文件名，通过原站保存入口提交，成功返回题目详情。下载验证文件逐字节一致。
- 补丁以 `new File([file], file.name, …)` 创建不带目录元数据的文件，保留 MIME、修改时间和二进制字节，再交给原站 input。
- 在真实页面模拟嵌套目录元数据，经过补丁的“选择文件夹 → 填入”逻辑追加两组，检查 File 和 multipart 仅含文件名。原站实际保存成功；下载的全部新增文件与备份内容逐字节一致。
- 清理本次三组临时记录，使用不缓存的请求重新核对原有一组、全部原始设置与文件字节。

自动化环境未能弹出原生文件夹选择框，因此目录元数据测试采用模拟输入；实际编码差异、服务端失败对照、补丁保存与下载回读均已验证。`tests/browser-batch-directory.js` 是无网络写入的浏览器回归测试；31 项自动测试覆盖二进制和空文件等情况。备份仅保存在本机 `tmp/accoding-batch-fix-10272/`，不发布测试数据。

## 本地功能检查

- 缺失答案时禁止填入，不改动现有行。
- `.in` 与 `.ans` / `.out` 自动配对，自然排序；原始文件字节不经解析或改写。
- 阻止同名文件覆盖、跨文件夹重名、同一输入同时对应 `.ans` 和 `.out`。
- 忽略隐藏文件与说明文档；ZIP 需先解压。
- 填入失败撤销本次新增行，恢复原站计数。

## 使用入口

题目编辑 → **基本设置** → **批量添加测试点** → 选择多个文件或文件夹 → 检查配对 → **填入 N 组测试点** → 检查权重 → 关闭设置窗口 → 原站 **保存**。

“填入”只修改本页表单，不会立即上传。当前采用追加模式，已有同名文件会报错；要替换已有点，先按原站方式处理旧数据。
