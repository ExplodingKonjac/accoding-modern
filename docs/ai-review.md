# 代码复核 1.20.4

历史代码对照默认收起，展开后仅读取当前选中的一份。跨题引用按历史提交所属运行读取；缺少运行编号时从该提交的完整运行中查找，并核对提交 ID、作者、比赛、题目和源码哈希。成功对照在本次详情中缓存；单份读取失败显示重试及原提交入口，人工核查和草稿继续保留。

画像默认显示人类可读的课程比赛名称、北京时间、历史覆盖缺口和具体习惯观察。参照代码描述截至最新资料的写法，不冒充当前提交之前的专用基线。版本、摘要、反馈水位和权限范围等字段收进「技术详情」。

核查列表、详情、源码、人工历史、画像与导出直接读取云端，不发送 Bearer，也不验证 OJ 账号或请求读取证明。画像异步加载，过时响应不会覆盖新提交或未保存草稿。新历史资料或助教结论触发重算时，每 45 秒刷新历史摘要。

默认选择 `publication_ready` 非 false 的最近一次完整运行，兼容未声明字段的历史运行。新运行上传中断时继续展示上次完整结果；没有完整版本时显示待同步。核查运行下拉可主动查看尚未发布完整的历史运行，并明确标为待同步。

新版名单默认显示「规则命中/未核查」「已核查为存疑」「已核查为AI」，分别计数；「全部代码状态」与「已核查为无AI」可查看人工排除记录。按 OJ 用户 ID 聚集，按题显示最后一份实际命中的代表提交。后续未命中提交不覆盖代表，每人题数不限。WA 只作历史对照。旧运行与旧人工记录保留，命名特征只在历史运行中可读，新版筛选和风险规则删除命名。

人工结论依次为「无 AI」「存疑」「有 AI」。未核查代码初始显示「请选择核查结论」，规则命中不预填人工结论，历史浏览器草稿仅恢复理由。保存需主动选结论、填写理由并点击按钮；沿用源码哈希、必填理由、修订冲突校验与请求幂等标识。存疑保存后留在复查队列。未知状态报格式错误，人工专属记录使用 `result:null` 与 `human_status`，不伪造机器判断。

v4 请求声明 `X-Review-State-Protocol: 2`。人工结论与理由可以立即编辑；仅点击保存时核实写入身份和三态协议能力。

列表显示评测结果、原始规则分、画像辅助分与人工理由。详情展示同题前版（可含 WA）、较早命中和重复 AC 时间线、源码哈希、真实 token 增删量、解析不可靠提示及规则排除说明。跨题对照不作算法 diff，同题历史可翻阅逐行 diff。来源与 AI 使用仍由助教核实。

成员长期画像读取服务端已同步的授权快照，展示采集覆盖、基线是否充分、输入与注释习惯、历场人工分布、证据提交、截止时间和反馈水位。权限覆盖不足或反馈修订后明确提示待重算；读取失败不阻止人工核查。分值不隐藏低分命中。保存反馈后立即把页面画像标为待更新。

浏览器可导出 JSON 与 XLSX，均读取最新同源码人工反馈。当前核查表包含所选名单、最后命中代表、评测与版本、两种分值和三态；完整证据表通过授权分页接口加载全场已冻结源码身份、所有命中事实、WA 对照与完整人工历史。XLSX 含「嫌疑名单」「助教反馈历史」「完整证据与对照」三表，标识和理由保持文本，避免公式执行。筛选或班级切换会取消过时导出。

已保留 1.19.6 的直接站点、e1/e2/e3 与路径型 VPN、XLS/XLSX 导入、名册共享和成绩导出能力。

# 代码复核 1.18.9

代码状态统一为「规则未命中」「规则命中/未核查」「已核查为AI」「已核查为无AI」。代码复核名单只显示「规则命中/未核查」和「已核查为AI」。超过复核限额但实际命中的代码仍保持「规则命中/未核查」，默认名单不收录；助教判定为 AI 后进入名单，判定为无 AI 后从名单移除。班级列表按 OJ 用户 ID 聚集，同一用户的提交相邻；可按题目、特征及这两种状态筛选。人工结论同步给其他助教。没有人工结论时，规则命中只表示待核查，不表示已确认使用 AI。

云端完整规则命中清单目前只回填最近一次 C2 运行。其他历史运行沿用原有保留候选名单。

从「按题查看通过提交」选择「进入本题代码核查」打开独立的本题提交核查页面，不自动打开某位学生的详情。该名单列出本题尝试者的具体提交：有 AC 的每人取最新一次 AC，没有 AC 的每人取最近两次尝试；默认显示所有四种代码状态，供助教逐条核查。首页「代码复核」名单独立运行，只显示待核查命中和已核查为 AI。学生提交记录也可直接打开对应详情。

详情右上角显示代码状态。左侧为本次提交，右侧快照可用按钮翻阅：跨题码风变化显示对照提交的具体题目及源码，不标增删颜色；同题上次提交显示逐行 diff，本次增加行标绿、上次减少行标红。没有更早提交时不着色。顶部上一页、下一页按当前名单顺序翻阅；返回列表时保留滚动位置。源码读取失败时显示错误，不会把失败误判为没有更早提交。

源码读取和人工保存分别处理：读取无需凭证；保存保留实名身份核实、必填理由、修订冲突检查和幂等重试。写入身份尚未验证或保存失败时保留当前草稿。仅点击保存时，从 OJ 当前登录主页取得用户 ID 和姓名，验证本场三份未公开源码的写入能力。私有指纹使用 `sha256("oj-review-write-proof-v2\n" + code)`，只将 CRLF/CR 规范为 LF；公开源码哈希无法替代该证明。写会话按 OJ 用户和比赛隔离，最多 8 小时，优先存于油猴 GM 存储；无 GM 时仅留当前页面内存。401/403 清除匹配的写凭证并重新验证一次，重试沿用原请求 ID。

人工反馈按提交 ID 和源码 SHA-256 绑定，跨规则运行保留。保存必填理由；云端记录助教身份、时间、当时的原始规则判定和每次修订。其他助教刷新即可看到最新结论。冲突时要求先读取最新历史，不覆盖他人的修改。请求失败保留页面草稿，重试使用同一请求标识。历史浏览器备注会填入编辑框，须主动保存后上传。

源码始终校验冻结哈希。未命中提交的身份来自云端已签名的整场源码清单，源码按需从已登录 OJ 读取。无法读取或摘要不匹配时停止保存。更正结论不会修改学生提交的代码。

独立提交检查页仍提供逐行 diff：删除为红底 `-`，新增为绿底 `+`，未变化为普通背景，并同时显示前后行号。

规则系统已取消模型核查。完整历史的每份提交均执行全部规则，再按命中结果去重限额：每人每题保留最早命中的一份，跨题按首次命中时间最多保留八份。最新提交没有命中也不会掩盖早期嫌疑。

普通说明至少三行；语言知识、明确对答与答案包装单独识别，不受普通行数门槛限制。知识识别补充格式符、类型转换、内存分配释放、地址与字符串机制。交错题比对同一学生在整场快照内各题的源码，去除空白、注释和预处理行后 token 相似度至少 90% 时排除时间类嫌疑，保留独立注释或输入检查线索。只有空骨架的短程序不会触发排除。

导出包含当前列表和该比赛的完整助教反馈历史，便于后续复盘和规则优化。模型历史结果作为旧运行记录保留；新任务、重试、连接测试及对照入口均不能启动模型。


## 提交检查页（1.18.0）

打开 `/submission/提交ID` 直接进入检查页。顶部显示作者、题目、时间和评测结果，源码保留原始空白并显示行号，可复制代码。点击“加载前后差异”查询同一学生在同一题目中早于本次的最近提交（包含未通过提交），以红色删除、绿色新增和双行号展示；首次提交、完全相同、读取失败分别提示。查询失败不会被当作没有前版。

页底 AI 判定复用班级代码复核的人工结论、必填理由、冲突处理与云端历史。页面展示的源码需与云端清单哈希一致才允许保存；未纳入清单时源码和 diff 仍可查看，但不能保存判定。刷新历史保留理由草稿。


## 码风与罕见高级用法（1.18.1）

短时间窗口为 360 秒（含边界）。代码内容变化仍使用去空白、注释后的 token 增删比例，至少 30% 命中；另行检测缩进一致性、运算符与逗号空格、命名习惯等多维码风变化。交错题高度匹配排除保持有效。

跨题比较不再强制需要注释，对照同一学生之前每道其他题的最新提交，要求命名习惯与至少两个排版维度同时变化。罕见高级用法检查非 I/O 内联函数、静态辅助函数、静态存储变量与函数指针；同题至少 20 名作者、使用率不超过 5% 才计为罕见。常见快读快写及其缓冲、游标和普通静态标量常量排除。所有命中是待人工核实的嫌疑线索。


## 长变量命名（1.18.2）

独立筛选实际声明并使用的 C 变量：至少两个变量名达到 8 个字符，或至少一个达到 16 个字符。函数名、宏、字符串与注释、普通标量常量、仅声明未使用的变量、快读快写函数及关联缓冲/游标不计入。与跨题命名习惯比较分别记录。


## 函数与变量命名（1.18.3）

在长变量名规则上新增：实际定义并使用的非 I/O 函数名达到 8 字符；函数或变量含至少两个分隔下划线（至少三个非空名称段），或符合 lowerCamelCase / UpperCamelCase。以上任一条件可进入嫌疑复核。变量长度门槛仍为两个达到 8 字符或一个达到 16 字符。保留注释、字符串、宏、常量、未使用声明、库函数和快读快写排除。

核查详情中的上一页、下一页会在保存后保持可用，并跳过已移出当前筛选名单的记录；一页记录核查完成后继续读取后续记录。右上角「查看该同学本次比赛提交」列出当前同学在本场比赛时间内的全部提交，包含所有题目、通过与未通过记录，支持按题筛选、分页和打开源码。返回当前核查时保留未保存理由及滚动位置。

云端历史若保存的是「OJ 用户编号」占位名称，页面按历史记录的助教账号 ID 读取其 OJ 资料并显示姓名；保留原始历史记录，不改动结论、理由或时间。新会话优先读取登录欢迎名称，缺失时读取该登录账号的资料页姓名。

历史参照后来被助教判为有 AI 或存疑时，画像汇总受影响提交数量，当前代码和历史条目显示具体失效原因。该冻结比较需要重新核查并重跑规则；刷新画像不会自动恢复其分值，因此此标记不启动 45 秒轮询。其他独立证据和有效余分继续显示，显式空分值不回退旧全局分值。
