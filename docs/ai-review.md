# 代码复核 1.17.3

提交结论只有「有AI嫌疑」「无AI嫌疑」；代码复核列表仅显示当前有嫌疑的提交。改为无嫌疑后从列表移除，仍可通过提交 ID 或源码页查看完整历史。查看提交后可修改结论并填写理由；原始规则依据与所有助教的修改历史保留。规则未命中的提交也可从学生提交列表、源码页或提交 ID 入口查看和修改，无额外人工分类筛选。

助教打开代码复核时自动验证当前 OJ 源码读取权限，无同步设置、额外账号或密钥输入。浏览器读取云端随机指定的三名其他学生的未公开源码，提交一次性摘要证明，取得该比赛 8 小时复核会话；OJ 登录 Cookie 留在 OJ。挑战样本由本机签名清单提供，并排除所有已公开规则记录和人工记录的源码哈希。挑战五分钟有效、一次使用；会话限制在对应比赛。历史中显示当前页面的 OJ 用户标识和名称；此验证证明源码读取能力，不是 OJ 签名的实名登录。

人工反馈按提交 ID 和源码 SHA-256 绑定，跨规则运行保留。保存必填理由；云端记录助教身份、时间、当时的原始规则判定和每次修订。其他助教刷新即可看到最新结论。冲突时要求先读取最新历史，不覆盖他人的修改。请求失败保留页面草稿，重试使用同一请求标识。历史浏览器备注会填入编辑框，须主动保存后上传。

源码始终校验冻结哈希。未命中提交的身份来自云端已签名的整场源码清单，源码按需从已登录 OJ 读取。无法读取或摘要不匹配时停止保存。更正结论不会修改学生提交的代码。

点击前后版差异时显示逐行 diff：删除为红底 `-`，新增为绿底 `+`，未变化为普通背景，并同时显示前后行号。

规则系统已取消模型核查。完整历史的每份提交均执行全部规则，再按命中结果去重限额：每人每题保留最早命中的一份，跨题按首次命中时间最多保留八份。最新提交没有命中也不会掩盖早期嫌疑。

普通说明至少三行；语言知识、明确对答与答案包装单独识别，不受普通行数门槛限制。知识识别补充格式符、类型转换、内存分配释放、地址与字符串机制。交错题比对同一学生在整场快照内各题的源码，去除空白、注释和预处理行后 token 相似度至少 90% 时排除时间类嫌疑，保留独立注释或输入检查线索。只有空骨架的短程序不会触发排除。

导出包含当前列表和该比赛的完整助教反馈历史，便于后续复盘和规则优化。模型历史结果作为旧运行记录保留；新任务、重试、连接测试及对照入口均不能启动模型。


## 提交检查页（1.18.0）

打开 `/submission/提交ID` 直接进入检查页。顶部显示作者、题目、时间和评测结果，源码保留原始空白并显示行号，可复制代码。点击“加载前后差异”查询同一学生在同一题目中早于本次的最近提交（包含未通过提交），以红色删除、绿色新增和双行号展示；首次提交、完全相同、读取失败分别提示。查询失败不会被当作没有前版。

页底 AI 判定复用班级代码复核的两种结论、必填理由、冲突处理与云端历史。页面展示的源码需与云端清单哈希一致才允许保存；未纳入清单时源码和 diff 仍可查看，但不能保存判定。刷新历史保留理由草稿。


## 码风与罕见高级用法（1.18.1）

短时间窗口为 360 秒（含边界）。代码内容变化仍使用去空白、注释后的 token 增删比例，至少 30% 命中；另行检测缩进一致性、运算符与逗号空格、命名习惯等多维码风变化。交错题高度匹配排除保持有效。

跨题比较不再强制需要注释，对照同一学生之前每道其他题的最新提交，要求命名习惯与至少两个排版维度同时变化。罕见高级用法检查非 I/O 内联函数、静态辅助函数、静态存储变量与函数指针；同题至少 20 名作者、使用率不超过 5% 才计为罕见。常见快读快写及其缓冲、游标和普通静态标量常量排除。所有命中是待人工核实的嫌疑线索。


## 长变量命名（1.18.2）

独立筛选实际声明并使用的 C 变量：至少两个变量名达到 8 个字符，或至少一个达到 16 个字符。函数名、宏、字符串与注释、普通标量常量、仅声明未使用的变量、快读快写函数及关联缓冲/游标不计入。与跨题命名习惯比较分别记录。


## 函数与变量命名（1.18.3）

在长变量名规则上新增：实际定义并使用的非 I/O 函数名达到 8 字符；函数或变量含至少两个分隔下划线（至少三个非空名称段），或符合 lowerCamelCase / UpperCamelCase。以上任一条件可进入嫌疑复核。变量长度门槛仍为两个达到 8 字符或一个达到 16 字符。保留注释、字符串、宏、常量、未使用声明、库函数和快读快写排除。
